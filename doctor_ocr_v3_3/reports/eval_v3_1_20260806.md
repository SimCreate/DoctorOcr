# v3_1 (Attention + 증강) — 최종 평가 보고서

> 날짜: 2026-08-06
> 목적: "attention 디코더가 데이터를 충분히 주면 CTC보다 좋다"는 가설의 검증
> 방법: v3_1 best_model (epoch 32, val_loss 1.3886) → beam search(5) → 클린 val 1,116장
> 비교: v3 exp2_clean(CTC) — 동일 val, 동일 지표, 동일 그룹핑

## 최종 결과 (동일 기준 공정 비교)

| 지표 | v3 exp2 (CTC) | v3_1 (Attention, beam=5) |
|---|---|---|
| exact match | **37.9%** (423/1116) | 30.4% (339/1116) |
| CER | **20.6%** | 38.2% |
| 고빈도 exact | 56.5% | 54.8% |
| 중빈도 exact | **33.5%** | 3.2% |
| 저빈도 exact | **8.0%** | 0.4% |
| 고빈도 단어수 | 476 | 602 |
| 판정 | FAIL | FAIL |

## 해석

1. **학습 로그(argmax 43.1%)가 실제 디코딩(beam 30.4%)보다 과대평가** — 교육 중 teacher-forcing과 자기생성이 섞인 로그 acc는 추론 성능과 별개다. 최종은 언제나 디코더 재평가로 판단.
2. **attention은 고빈도에서만 작동** (54.8% ≈ CTC 56.5%), 중·저빈도는 붕괴 (3.2% / 0.4%). 드문 단어는 통째로 오생성 → CER 급증(38.2%).
3. **CTC가 실질 우위** — exact 37.9% vs 30.4%, CER 20.6% vs 38.2%. 중·저빈도에서 CTC가 부분적으로라도 정답을 건짐.
4. **가설 결론**: "데이터가 attention 수렴을 살린다" = 부분 검증 (v2.1 원본 20% → 30.4% 향상). "attention이 CTC보다 좋다" = **기각**.

## 원인 후보 (추가 실험 시)

- attention 디코더가 augmentation noise에 취약 — 증강 이미지가 라벨 순서/불변 패턴을 흐림
- teacher forcing 0.47→0 스케줄이 짧았거나, beam search 구현이 단순 (재정렬/길이 보정 없음)
- 롱테일(1회 등장 64%)은 디코더 방식과 무관하게 데이터 양 문제 — 라벨 정제가 근본 축

## v3_1 전용 확장 지표 (2026-08-06 추가)

attention beam search의 오류 특성을 정량화하기 위해 v3_1 평가 레이어에 추가한 고유 분석
(v3에는 없음 — 레거시의 기본 지표에 확장).

| 지표 | 값 | 의미 |
|---|---|---|
| beam oracle (top-5 후보에 정답 포함) | **42.6%** (475/1116) | top-1(30.4%)보다 +12.2p — 모델이 **"거의 맞았으나 순위를 못 매긴"** 케이스 |
| oracle gain (top-1 틀렸으나 후보에 정답) | 136장 (12.2%) | beam 재순위/길이 보정으로 회수 가능한 여지 |
| oracle 고빈도 | 72.3% | 고빈도에서 top-1 54.8% → 후보로는 72.3%까지 — 후보 품질은 괜찮음 |
| oracle 중빈도 | 15.3% | 중빈도는 후보에도 거의 없음 (근본적으로 못 봄) |
| oracle 저빈도 | 2.6% | 저빈도는 후보에도 거의 없음 |
| 반복토큰 비율 (연속동일문자≥3) | 1.8% (20/1116) | `Raviiil`, `Mariiii` 식 attention 반복 생성 — 소수지만 치명적 오류 유형 |

### 해석

1. **beam oracle 42.6% vs exact 30.4%**: top-1만 따지면 30.4%지만, 후보 5개 안에는 42.6%가 포함 —
   모델 표현력 자체가 무너진 게 아니라 **ranking/디코딩 문제**가 일부 있다는 근거.
2. **중·저빈도는 후보에도 없다** (15.3% / 2.6%): 이건 디코딩 문제가 아니라 **인코더가 이미지를 못 읽은 것** —
   beam을 넓혀도 회수 불가. 라벨 정제/데이터가 근본 해결책.
3. **반복토큰 1.8%**: attention 특유의 mode collapse가 여전히 존재하나 빈도는 낮음 (v2.1 원본 대비 크게 줄어든 상태).
