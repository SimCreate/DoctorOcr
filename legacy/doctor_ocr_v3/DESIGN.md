## 3. 평가 레이어 설계 (Q2 — 확정)

기존 exact match 방식의 한계:
- 정확히 일치해야 1점, 글자 하나 틀리면 0점 → 정보 손실 큼
- 전체 6% 숫자 하나로는 어느 그룹이 막혔는지 알 수 없음

### 3.1 지표
1. **CER (Character Error Rate, 문자 오류율)**
   - 맞춘 글자 대비 틀린 글자 비율
   - "femotol" → "femotoll"은 exact match 0점이지만 CER은 낮음 → 작은 오류 vs 쓰레기 출력 구분 가능
2. **라벨 빈도 그룹별 분리 채점**
   - 고빈도(10회↑) / 중빈도(2~9회) / 저빈도(1회) 별 정확도 집계
   - 전체 평균 하나로 가려지는 문제 해결

### 3.2 수용 기준 (acceptance threshold)
- **고빈도(10회↑) 그룹 정확도 ≥ 90%**
- **전체 CER ≤ 20%**
- 두 조건 모두 충족 시 "실사용 시작 가능" 판정

## 4. 데이터 전략 설계 (Q1 — 실험군 3, light-touch 합성)

### 4.1 합성(합성 데이터)에 대한 논의 — 3등급
1. **순수 폰트 렌더링** — 위험: 도메인 갭 (폰트 vs 실제 손글씨 통계 다른 세계)
2. **실사 이미지 변형 증강** — 안전: 실제 이미지에 회전/노이즈/변형, 라벨 유지
3. **하이브리드** — 고빈도=실데이터+실사증강, 저빈도=합성으로 "어휘 노출"만

사용자 선택: 실험군 3, **저빈도 합성은 "거의 건들이지 않는 정도"(light-touch)**.

### 4.2 실험군 정의
- **실험군 1 (baseline)**: 실제 데이터만 — 현재 상태 (6.18%)
- **실험군 2**: 실사 이미지 변형 증강만 (순수 합성 없음)
- **실험군 3**: 실험군 2 + 저빈도(1~2회) 라벨의 light-touch 합성

### 4.3 구현 세부 (확정된 가드레일)
- 합성 대상: 1~2회 출현 라벨만. 3회 이상은 실사 증강만.
- **비중 캡: 에포크당 합성 샘플 10~15% 이하** (85%+는 실제+실사증강)
- 합성 샘플에 마킹(marker) → 학습은 섞되, **분석/평가시 합성 샘플은 분리 집계**
- 라벨은 실제와 동일 (fake 라벨 생성 금지 — 7/25에 78개 fake라벨로 데인 전례 있음)
- 기대치: 롱테일 완전 정복 아님. 목표는 (a) 고빈도 정확도 상승 (b) 저빈도/회귀 무해

### 4.4 합성 검증 원칙 (네 의문을 실험으로 끝내기)
판정 기준: 실험군 3이 실험군 2를 고빈도 그룹에서 못 이기면 → 합성 폐기.
합성이 이득인지 해로운지를 주장이 아닌 측정으로 결정.
